# Security Policy

## Reporting a vulnerability

Do not publish suspected vulnerabilities, credentials, personal data, calendar data, or deployment details in a public issue.

Use GitHub's private vulnerability reporting or draft Security Advisory feature for this repository. Include only the minimum information necessary to reproduce the issue, redact credentials and personal data, and avoid attaching real household schedules, photographs, calendar exports, or logs.

## Scope

This repository is a sanitized portfolio case study. It contains no production credentials, live deployment configuration, real household data, or supported public service endpoint.

## Response priorities

1. Contain exposure and make affected public content private when necessary.
2. Revoke and rotate any exposed credential before repository cleanup.
3. Remove sensitive data from files, history, artifacts, releases, caches, and forks when possible.
4. Document the cause and add a preventive control before republishing.
